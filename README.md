# Агент поддержки магазина ПО — прототип для ИИкузницы (трек «Клиентские сценарии»)

Чат-агент для покупателей интернет-магазина программного обеспечения (задача Softline,
store.softline.ru). Помогает выбрать продукт и вариант лицензии, отвечает на вопросы по сведениям
о продуктах и базе знаний, готовит черновик КП по шаблону компании для проверки менеджером
и передаёт менеджеру то, что требует решения человека.

## Бизнес-проблема → что делает решение

| Из карточки задачи | Решение |
|---|---|
| Консультация перед покупкой, особые условия, наличие и сроки | Агент подбирает продукт и вариант лицензии, называет цену, НДС и срок поставки; особые условия (скидка больше 5%, нестандартная оплата, тендер) — на доску «Ждут решения» менеджеру |
| Штат в разных каналах — чат, почта, телефон | Один агент и одна лента для всех каналов: виджет на сайте, почта (IMAP/SMTP), звонки — расшифровка речи через API `/api/channels/inbound` (в панели есть имитация письма и звонка), Telegram |
| 15–30 минут на диалог, 1000–2000 обращений в месяц = 500–1000 человеко-часов | Типовые диалоги агент закрывает сам за секунды; в сложных менеджер получает готовую сводку и черновик ответа. Сводка считает сэкономленные часы и стоимость ИИ против работы сотрудников на плановую нагрузку |
| Нет базы знаний, 30–40% вопросов повторяются | База знаний с поиском по смыслу формулировок; ответ менеджера на новый вопрос становится кандидатом в базу; переписки поддержки загружаются как примеры; сводка показывает частые вопросы и вопросы без ответа |
| КП и счёт вручную — плюс 10–20 минут к сделке | Черновик КП по шаблону компании (и счёт) формируется в диалоге за секунды, менеджер утверждает одной кнопкой |
| Медленная реакция — теряется 10–15% обращений | Первый ответ сразу, 24/7; передача менеджеру с таймером SLA 2 мин и напоминанием при просрочке; список «сделок под риском» (КП без счёта, неоплаченные счета) |

Нагрузка в материалах указана по-разному: в карточке — 1000–2000 обращений в месяц, на слайде кик-оффа —
около 500 в день. Плановая нагрузка для расчёта экономики задаётся в «Настройках» (по умолчанию 1500 в месяц).

## Что закрыто из задачи

| Требование | Как реализовано |
|---|---|
| **Клиент знает продукт** («нужен MDaemon Standard») — сверить версии, при нехватке данных задать вопросы | Каталог хранит варианты продукта: редакция, срок, число пользователей/устройств, новая лицензия или продление, развёртывание. Инструмент `select_variant` подбирает точный артикул и возвращает **только недостающие параметры** с доступными значениями — агент спрашивает ровно о них. Если запрошенной версии нет — говорит об этом и предлагает ближайшую |
| **Клиент не знает решения** («защитить почту и файлы на 50 сотрудников») — выяснить требования и подобрать | До трёх вопросов за раз (задача и масштаб, инфраструктура, требование российского ПО/сертификатов, бюджет) → 2 варианта с обоснованием и ориентировочной стоимостью → рекомендация |
| **Ответы на вопросы по сведениям о продуктах** | Ответы только из карточки продукта и базы знаний, со ссылкой на страницу продукта или источник. «Есть ли российский аналог?» — `find_alternatives` по реестру российского ПО |
| **Обезличенные переписки поддержки** | Загружаются в «Переписки поддержки» (JSON/CSV/XLSX/TXT), дополнительно маскируются e-mail, телефоны, ИНН. Агент использует их как примеры реальных формулировок (`search_support_examples`); пару можно отправить в базу знаний |
| **Каталог в виде фида, ~200 000 позиций** | Импорт YML (Яндекс.Маркет), Google Merchant XML, CSV/XLSX, JSON. Атрибуты ПО берутся из параметров оффера или распознаются из наименования. Поиск — SQLite FTS5 + переранжирование: на 200 000 SKU медиана ~0,1 с (`scripts/bench_search.py`) |
| **КП по шаблону** (дополнительно) | После согласия клиента — черновик КП в формате шаблона компании: «Куда», «Исх. №», таблица «Артикул / Наименование / Кол-во / Цена / Сумма / В т.ч. НДС», условия оплаты, срок поставки, срок действия. HTML (печать/PDF) и DOCX. Помечен «ЧЕРНОВИК», пока менеджер не утвердит |
| Ответы организаторов: **постоплаты нет** | Агент не обещает отсрочку: отвечает правилом 100% предоплаты и по желанию клиента подключает менеджера |
| **Скидку до 5% агент даёт сам, больше — менеджер** | Ограничение в коде расчёта, а не в промпте: модель не может обойти лимит. Запрос больше 5% → карточка «Ждут решения» → менеджер согласует → КП пересчитывается и уходит клиенту |
| **Менеджер отвечает за 2 минуты** | SLA 2 мин в настройках: срок называется клиенту, на доске «Ждут решения» — таймер, просрочка подсвечивается и вызывает повторное уведомление |
| Видео-сцена с письмом клиента | «Входящее письмо» в панели — имитация почтового канала (при настроенном IMAP/SMTP письма забираются автоматически). Письмо с несколькими просьбами (продление + отсрочка) разбирается целиком |
| «Стоимость использования» | Сводка считает стоимость ИИ по фактическим токенам: за период, на один диалог и прогноз на плановую нагрузку (500 обращений/день) против стоимости работы сотрудников — нормативы задаются в «Настройках» |

Ограничения задачи («готовые интеграции с API не предусмотрены», «масштабируемость не обязательна»)
учтены: всё работает локально на файлах-выгрузках. Внешние каналы (почта, Telegram, телефония через API)
подготовлены, но включаются только настройками.

## Запуск через Docker Compose

Требуется Docker Engine с плагином Compose v2.

```bash
cp .env.example .env
# Задайте хотя бы ADMIN_PASSWORD и SECRET_KEY в .env
docker compose up --build -d
```

- Демо-витрина: http://localhost:8000/demo
- Панель менеджера: http://localhost:8000/admin
- База данных и загруженные модели хранятся в Docker volume `agent-data`

Можно изменить порт хоста через `APP_PORT`, например `APP_PORT=8080 docker compose up -d`.
Все параметры из `.env.example` поддерживаются Compose через переменные окружения.
Остановить приложение: `docker compose down`; остановить и удалить данные:
`docker compose down -v`.

### Режимы ассистента

- **Офлайн (по умолчанию)** — внутренние модели: ассистент на правилах, поиск по каталогу и базе знаний,
  собственный классификатор обращений и нейросеть, дообученная на переписках. Работает без интернета,
  проходит все сценарии задачи.
- **ИИ-режим (необязательно)** — подключение языковой модели по API: ключ `LLM_API_KEY` в `.env`
  (см. `.env.example`). Модель ведёт диалог свободнее, но факты берёт только из тех же инструментов
  (каталог, база знаний, расчёт). Если API недоступен, диалог автоматически подхватывает офлайн-ассистент.

## Загрузка материалов задачи

Материалы с Google Диска задачи (в git не входят) кладутся в `materials\drive\`:
`Mindbox.yml.gz.xml` (фид) и `chats.zip` (распакованный в `materials\drive\chats\`).

1. **Каталог (feed)** — большой фид загружается скриптом (2–3 минуты, потоковый разбор, gzip поддерживается):

   ```powershell
   .venv\Scripts\python scripts\import_feed.py materials\drive\Mindbox.yml.gz.xml
   ```

   Небольшие фиды можно загрузить и в панели: «Каталог (фид)» → «Загрузить фид». Что берётся из фида
   store.softline.ru (136 040 офферов → ~14 тыс. продуктов): «Тип лицензии» (новая / продление / обновление /
   техподдержка), «Срок действия», «Тип организации» (коммерческая / академическая / государственная — цены
   разные), «К-во узлов» (нижняя граница диапазона цены за узел — верхняя достраивается), «К-во пользователей
   до» (пакет), `available` (продаётся ли сейчас), номер в реестре отечественного ПО. Варианты одного продукта
   объединяются по наименованию и `group_id`. Признак российского ПО и НДС 0% ставятся по номеру в реестре,
   а если его нет — по списку российских вендоров (эвристика; уточните, если в выгрузке есть точные данные).
   После загрузки реального фида демо-каталог скрывается.
2. **База знаний** — «База знаний»: статьи «вопрос — ответ» со ссылкой на источник, импорт CSV.
   Стартовые статьи составлены по store.softline.ru/delivery_info и docs.softline.com (пересказ со ссылками)
   и правилам, озвученным организаторами.
3. **Обращения из чатов** — «Переписки поддержки» → загрузить `buy_part_*_masked.txt`. В выгрузке задачи —
   495 обращений клиентов с категорией и страницей сайта (без ответов поддержки). Они используются как реальные
   формулировки для агента, как статистика спроса и как проверочный набор:

   ```powershell
   .venv\Scripts\python scripts\evaluate_chats.py materials\drive\chats
   ```

   Отчёт — `reports\chats_eval.md` (сводка по категориям) и `reports\chats_eval.csv` (каждое обращение и ответ).
4. **Шаблон КП** — реквизиты, обращение, подписант и примечания — в «Настройках» → «Компания и шаблон КП».
   Банковские реквизиты для счёта не заполнены — укажите их, если нужен счёт.

## Сценарий демонстрации (для питча)

На реальном фиде (проверено офлайн-режимом):

1. **Знает продукт.** «Нужен MDaemon Standard» → в фиде редакции Standard нет, агент находит MDaemon и
   спрашивает число пользователей, тип покупки и срок → «на 30 пользователей, новая лицензия, на год» →
   сообщает, что годовой лицензии у этого варианта нет (есть 2 и 3 года), и уточняет срок → «а есть
   российский аналог?» → российские продукты для почты из каталога со ссылками.
   На демо-каталоге: пакет до 50 польз. и CommuniGate Pro / RuPost в аналогах.
2. **Не знает продукт.** «Не знаю, что нужно, но хотим защитить почту и файлы на 50 сотрудников» → вопросы
   про реестр и сервер → два варианта с обоснованием и суммой → «второй вариант» → «сделайте КП» →
   черновик КП по шаблону.
3. **Продление и особые условия.** «Продлить Касперский Стандартный на 40 компьютеров на год» → агент
   уточняет тип организации (у коммерческих и образовательных разные цены) → «коммерческая» → артикул
   `KL4863RAPFR`, 40 узлов × 1 969,20 ₽ = 78 768 ₽, без НДС (ПО из реестра) → «можно с отсрочкой?» →
   правило предоплаты → «дайте скидку 10%» → агент сразу даёт 5% и передаёт запрос → в панели «Ждут решения»
   таймер 2 мин → «Согласовать 10%» → клиент в чате получает обновлённое КП.
   Со страницы продукта: «сколько стоит лицензия?» на странице RedCheck → агент понимает, что речь о RedCheck.
4. **Письмо и звонок.** «Входящее обращение» → письмо Ольги (продление + отсрочка) → ответ агента, диалог в
   канале «Почта»; вкладка «Звонок» — расшифровка речи («почтовый сервер, человек на тридцать») → агент
   уточняет только недостающее. Все каналы — в общей ленте.
5. **Сводка** — решённые без сотрудника, скорость ответа, время решения менеджера, стоимость ИИ на диалог.

## Проверка на реальных обращениях (офлайн-режим, без ИИ)

Прогон всех 495 обращений из выгрузки чатов на полном фиде (136 040 офферов), `reports\chats_eval.md`:

- без передачи менеджеру — 75% (уточняющие вопросы, подбор варианта, список подходящих продуктов);
- передано менеджеру — 25% (продолжения разговора по заказу, продукты вне каталога, особые условия);
- ответ в среднем за 0,5 с.

Это покрытие, а не качество. Ручная проверка 25 случайных ответов «подобран вариант»: 14 верно,
2 частично, 9 ошибочно. Ошибки — запросы, которые надо понимать по смыслу (аксессуар к модели, «Касперский в
школу», «Siemens NX», транслит «энидеск»). Правила здесь упираются в предел: офлайн-режим — страховка на
случай недоступности ИИ-режима, который лучше понимает свободные формулировки. Чтобы оценить ИИ-режим на том же наборе:

```powershell
$env:EVAL_LLM_API_KEY = "<ключ>"; .venv\Scripts\python scripts\evaluate_chats.py materials\drive\chats
```

Что офлайн-режим делает безопасно: если продукт назван неуверенно — предлагает список, а не утверждает;
если названного бренда или модели нет в каталоге (anydesk, uipath, UX8406CA) — говорит об этом и передаёт
менеджеру; продолжения разговора («счёт ждём», «отправлял запрос») сразу уходят менеджеру.

## Классификатор обращений

Модуль `app/services/classifier.py`. Каждое обращение из чата, почты или звонка получает две метки:

- **Тип обращения** — 9 категорий разметки переписок Softline: цена, конфигурация, доступность вендора,
  счёт/КП, физлицо, скидки, госзакупки, follow-up, прочее. Модель обучена на 495 размеченных чатах
  (загружаются в «Переписки поддержки»).
- **IT-тема** — справочник из 31 категории и 359 ключевых слов (`app/resources/it_topics_handbook.json`),
  дополняется в панели через облако слов.

Как устроен:

- модель на словах и символьных n-граммах (логистическая регрессия) плюс нейросеть rubert-tiny2,
  дообученная на переписках: по умолчанию 70% и 30%. Для сравнения есть базовый вариант
  «TF-IDF + наивный Байес», он выбирается в панели;
- справочник ключевых слов важнее модели. Слова сверяются по границам и с учётом окончаний, поэтому ключ «ПО»
  не срабатывает на «почему», а «права» — на «правительство». Русские написания брендов приводятся
  к латинице справочника («Касперский» → Kaspersky);
- ниже 80% уверенности обращение попадает в очередь «На проверку». Подтверждение или исправление
  менеджера становится обучающим примером, и модель дообучается.

Где виден результат:

- столбец «Тип обращения» в списке диалогов;
- блок «Классификация» в диалоге (с исправлением одной кнопкой);
- строка в уведомлении менеджеру;
- подсказка ИИ-агенту на первом ходе;
- страница «Классификатор»: очередь на проверку (подтверждение одной кнопкой «✓ Верно»), спорная разметка,
  облако слов для IT-тем, статистика и проверка текста, справочник, модель и обучение;
- счётчик обращений на проверку в меню.

### Точность

Оценка на 495 чатах по исходной разметке выгрузки (`scripts\evaluate_classifier.py --original`). Каждый
пример проверяется моделью, которая его не видела при обучении (кросс-валидация, 5 блоков). Оценка по
проверенной разметке — ниже, в разделе про спорную разметку.

| Вариант | Точность | Уверенных ≥80% | Из них верно |
|---|---|---|---|
| базовая модель (TF-IDF + наивный Байес) | 60% | 22% | 81% |
| базовая модель + справочник типов обращений | 65% | 29% | 82% |
| логистическая регрессия + справочник | 73% | 41% | 87% |
| **гибрид с дообученной rubert-tiny2 + справочник (по умолчанию)** | **75,6%** | 38% | 87% |

Гибрид проверен на двух разных разбиениях: на одном прирост 71,7% → 75,6%, на другом 73,9% → 75,6%.
Вес нейросети 30% оказался лучшим на обоих. Если всегда отвечать самой частой категорией, точность будет 26%.

Что ещё пробовалось и не дало прироста:

- стемминг, маскирование чисел и названий;
- признаки страницы сайта, параметров лицензии, намерений из правил агента и совпадения с каталогом;
- SVM и ансамбль с наивным Байесом;
- готовые векторы rubert-tiny2 без дообучения (62%);
- синтетические обращения: 270 штук, по 30 на категорию (`samples\synthetic_requests.json`). Они добавлялись
  только в обучение, проверка шла на реальных чатах. У TF-IDF-модели общая точность не изменилась (73,2% →
  73,1%), хотя редкие категории стали находиться лучше (полнота 57% → 66%). У гибрида с нейросетью точность
  упала: 75,6% → 74,3%. Синтетика написана «по определению» категорий, а реальная разметка следует своим
  привычкам («КП на конкретный продукт» = «Конфигурация»), поэтому в рабочую модель она не добавлена.

Точность упирается в разметку. Разбор уверенных «ошибок» показал, что примерно в половине случаев права
скорее модель: «можете оформить КП на артикул» в разметке стоит как «Конфигурация», «выставьте нам счёт»
— как «Прочее». Поэтому в панели есть раздел **«Спорная разметка»**: 26 чатов, где модель, не видевшая
пример при обучении, уверенно ставит другую категорию. Менеджер подтверждает или исправляет метку.

Все 26 спорных чатов проверены вслепую: видны были только текст и список категорий, без исходной метки
и ответа модели. Итог:

- 16 раз выбрана та же категория, что у модели;
- 5 раз — та же, что в исходной разметке;
- 5 раз — третья категория (например, «запросил КП, ответа нет» — это Follow-up);
- изменена 21 метка.

С проверенной разметкой в роли эталона (`reports\classifier_eval.md`) точность такая:

| Вариант | Точность | Уверенных ≥80% | Из них верно |
|---|---|---|---|
| логистическая регрессия + справочник | 75,3% | 40% | 93% |
| **гибрид с rubert-tiny2 (по умолчанию)** | **78,0%** | 38% | **95%** |

Оценка по исходной разметке: `--original`.

Учить модель на проверенных метках пока не стоит: на 474 неизменённых чатах точность упала с 76,4% до 75,0%.
По новому правилу исправлена 21 метка, а ещё около сотни похожих чатов размечены по старому, и модель
получает противоречивые примеры. Поэтому проверенные метки служат эталоном оценки. В обучение их
включает настройка «Учить на проверенной разметке», и делать это стоит, когда все чаты будут размечены
по единому правилу.

Кривая обучения ещё растёт: на 99 / 198 / 297 / 396 обучающих примерах точность 64 / 69 / 71 / 73%.
Исправления менеджеров добавляют примеры, и каждое удвоение выборки даёт ещё +2–4 п.п.

### Облако слов для IT-тем

На странице «Классификатор» есть облако частых слов из обращений, для которых справочник не нашёл IT-тему.
Сейчас без темы 380 обращений из 500, и чаще всего в них встречаются microsoft, криптопро, csp, office, adobe,
альт, ред, astra. Например, тем «Операционные системы», «Офисные программы» и «Электронная подпись»
в справочнике пока нет.

Как пользоваться: перетащите слово на тему или нажмите слово, а затем тему. Если подходящей темы нет,
создайте новую. Слово сразу становится однозначным ключевым словом темы: одного такого слова в обращении
достаточно для уверенной темы. Переобучение не нужно, IT-темы у текущих диалогов пересчитываются сразу.
Слова не о технике можно скрыть.

Для типа обращения облако не используется, это проверено на 495 чатах. Если отнести каждое частое слово
к его самой частой категории, верными будут 41% меток. Группы похожих по смыслу обращений дают 38–50%.
Модель на тех же неуверенных обращениях верна в 69%, так что массовая разметка по словам её бы ухудшила.
Тип обращения подтверждается поштучно в очереди «На проверку».

### Нейросеть: установка и обучение

Нейросеть необязательна: без неё гибрид работает как TF-IDF-модель.

```powershell
.venv\Scripts\pip install -r requirements-ml.txt
```

```powershell
.venv\Scripts\python scripts\download_model.py
```

Первый пакет — PyTorch CPU и transformers, около 1 ГБ на диске. Второй шаг скачивает модель
cointegrated/rubert-tiny2 (119 МБ) в `data\models
ubert-tiny2`.

Дообучение на CPU занимает 5–10 минут и идёт в фоне: при первом запуске, по кнопке «Дообучить нейросеть»
и само, когда накопится 30 новых размеченных примеров. Пока оно идёт, работает прежняя версия. Классификация
одного обращения с нейросетью занимает около 50 мс. Полная оценка гибрида (нейросеть дообучается в каждом блоке,
около 25 минут):

```powershell
.venv\Scripts\python scripts\evaluate_classifier.py --neural
```
